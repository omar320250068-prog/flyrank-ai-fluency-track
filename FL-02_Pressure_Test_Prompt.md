## Prompt to paste (exact text)

```
You are my tutor for an 8-week portfolio build. My proof statement:
"I ship AI-assisted things."
My one person: a FlyRank reviewer.
My one action: get them to try the live project.

Sitemap I'm proposing:

1. HOME — hero with the claim + one big CTA button: "Try the live project"
2. PROJECTS — two short case studies; the live project is pinned first with a CTA
3. ABOUT — 6 lines max: who I am, how I work with AI, human-in-the-loop standard
4. Contact: one email/DM line in the footer on every page (no separate page)

Pressure-test this sitemap against:
(a) my one action — does every page move the reviewer toward trying the live project?
(b) my claim — does every page earn its place by proving "I ship AI-assisted things"?

For each page, give a one-line verdict: KEEP / CUT / MERGE and why.
Then give me the smallest version of the map that still proves the claim.
Finally, tell me exactly one thing I should change and why.
```

---

## Answer to save (screenshot this version or run it yourself)

**Page verdicts:**

| Page | Verdict | Why |
|------|---------|-----|
| Home | **KEEP** | States the claim, carries the primary CTA to the live project — the entire purpose of the site. |
| Projects | **KEEP** | This is the proof: real work that shipped. The live project is pinned with a CTA, so even if they stop here, they hit the action. |
| About (6 lines) | **KEEP — but cut to one card.** | Gives the reviewer just enough context (who, how) without becoming an essay that delays the action. Any longer and it's a distraction. |
| Contact (footer) | **KEEP as footer only** | Exactly right: never a page, but a persistent escape hatch if they want to reach out after trying the project. Good. |

**Smallest map that still proves the claim:**
Home + Projects = **two pages** (with About folded into the Projects page as a one-card footer block). This would still prove the claim and push the action. But four elements (three pages + footer CTA) works and feels complete. Recommended: stick with three pages.

**One thing I would change:**
**Add a live interactive preview on the Projects page**, not just a description of the project. Right now, a "Try the live project" button asks the reviewer to leave the portfolio and go elsewhere — that's friction. If you can embed a short, working demo (even a simple iframe, a screenshot with a hot-spot, or a 30-second screen recording), the reviewer can try it without leaving the page. That increases action completion.

> **Change I'm taking away:** add an embedded mini-preview or short screen recording of the live project on the Projects page before the external CTA. This removes friction between believing and trying.
